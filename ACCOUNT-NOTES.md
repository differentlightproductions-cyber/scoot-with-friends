# Game accounts

The public Sites Worker exposes same-origin `/api/account/{session,register,login,logout,recover,delete,save}`. D1 `DB` stores case-folded unique usernames, salted PBKDF2-SHA256 hashes (600,000 iterations using @noble/hashes), hashed random session/recovery credentials, and atomic request counters. Cookies are Secure, HttpOnly, SameSite=Strict, host-only, seven days. JSON mutations check Origin and size. No password, recovery code, or session token is logged or saved in browser storage. Recovery codes are one-use and replace passwords/revoke sessions. Username Charizard495 remains reserved pending owner provisioning; registration never grants privileges.

Cloud save (`save`, D1 table `game_saves`, migration 0001): while signed in, the game copies the device's saved profile (loadout, avatar, alpha Credit, owned parts, XP, missions, crates, settings) to the account so it follows the player to other devices. GET returns the account copy and its revision; POST `{data, base, force}` stores a new copy only when `base` matches the stored revision (or `force` after the player chose this device), otherwise 409 with the stored copy. Saves are JSON objects up to 64 KB, rate-limited per account, and deleted with the account. The client (`src/data/cloud.ts`) never merges: an unchanged device pulls, a changed device pushes, and when both changed the player picks one in the account dialog (the replaced device save is kept locally as `lazer-profile-before-cloud-v1`). The cloud copy is written by the client, so it is not a secure wallet: it adds no admin privileges, and anything bought with real money later must be granted and verified server-side, never read from a save. It does not connect the internet room server. Local/portable copies remain playable without login and explain that online accounts require the published website. The previous Node SQLite accounts/starter store is not the deployed D1 identity database and is not silently migrated.

Deploy the existing Sites project with `d1: DB`, preserving `r2: PARKS`. The build copies ordered SQL migration and Drizzle journal into `dist/.openai/drizzle`. Never commit a database or actual credentials. User account creation must happen in the game UI, not through chat. Account deletion requires an authenticated session and current password; it leaves local game progress untouched.

Tests: `npm test` (includes tests/auth-api and tests/cloud-save), `npm run build`, `node tests/cloud-save.browser.mjs`, `node tests/menu-focus.browser.mjs`, `node tests/ui-polish.browser.mjs`. Real registration/login/session/recovery must also be checked on the deployed Worker because password hashing depends on host execution limits.
